# Operator guide

For trading comps, DCF, dated filings, exception review and valuation PDF export, follow the [valuation workspace guide](VALUATION_PLATFORM.md). The instructions below describe the annual-report workflow. When clearing an annual data body in a disposable workbook copy, include the four appended provenance columns through AQ.

Use the assembled .xlsm on Windows Excel Desktop; the .xlsx is a development shell. Open the workbook from a writable local folder. The supplied reports and populated workbook remain viewable without running macros. Normal use does not need programmatic VBA project access.

## First run and workflow
Home has eleven controls. Import selects any number of input files. Clean normalizes the raw ledger; Validate repeats cleaning and builds accepted statements; Calculate repeats these stages and creates the formula sheet. Refresh Dashboard, Generate Report, Export PDF and Run full workflow rebuild the analysis from Raw_Data. Apply banking formatting styles the data sheets and scans them for formula errors. View automation log shows timestamps, outcomes, counts and seconds. A successful stage can contain rejected records: check Settings and Clean_Data.

Import **appends** to the raw ledger. For a fresh portfolio, work on a separate copy of the workbook: clear the entire data body under the Raw_Data headers (all 43 columns; preserve row 1), import your files, and run the full workflow before using outputs. After an import, the previous views remain a snapshot until the workflow is refreshed. Never edit derived rows as a correction. If a restatement is intentional, archive a workbook copy, correct the upstream extract, and rebuild in an empty copy using only the approved version.

Reset demo data requests confirmation, saves a timestamped workbook backup, and reads all six demo files before replacing raw records. If any input cannot be read, the existing raw records remain. Save the workbook to retain new analysis and audit entries. The audit log is an operating record, not a tamper-proof ledger.

## Input contract
- One row per company and fiscal year: annual, consolidated, whole-company actuals. Do not mix quarters, segments, standalone statements, forecasts or different accounting bases. For a machine-readable declaration, include optional column `Statement_Basis` with `Annual consolidated actuals` on every row. An incompatible explicit basis rejects the file. With no declaration, using the template means the preparer has confirmed this scope; the software cannot infer the basis from numbers.
- Use [the template](../templates/import_template.csv) header names. Order and case can vary; surrounding header spaces are ignored. Required headers: Company_ID, Company_Name, Reporting_Period, Period_End_Date, Currency, Units, Revenue. Other financial items are optional. Extra columns are ignored. A blank optional input is unknown; it can disable specific metrics without invalidating the filing.
- CSV: UTF-8, comma delimiter, doubled quotes, including quoted commas and newlines. XLSX: first worksheet, headers in row 1, one rectangular data block. Open source read-only; supply saved values. Use CSV/XLSX only. Close an input already open in the active Excel instance. Keep the original source for an archival copy; Raw_Data captures mapped values, not source styles or formulas.
- Dates: ISO YYYY-MM-DD preferred; slash dates are **month/day/year**. Excel numeric date cells, including a 1904-date workbook, are interpreted using the source date system. A fiscal year label is FY followed by the four-digit year of the period end. Noncalendar year ends are supported; stub periods and 52/53-week YoY alignment are outside scope.
- Units: Actual/Units, Thousands, Millions or Billions. The scale applies to all amounts **and shares**, except Stock_Price, which is currency per one share. The normalized scale is millions. Currency must be USD, EUR, GBP, INR, CAD, AUD, JPY, CHF, CNY, HKD or SGD. Numeric CSV text uses a decimal point; grouped thousands must be quoted and correctly grouped. Accounting parentheses denote negatives. Do not include currency symbols in numeric fields.
- Revenue is mandatory; zero revenue is legitimate, negative revenue is rejected. Use positive expense magnitudes for COGS, interest and tax, with negative tax allowed for benefits. Where inputs are available the gross-profit, net-income and balance-sheet identities must reconcile within the documented tolerance.

## Review, reports and records
Raw_Data retains every mapped source row. Clean_Data is a row-by-row decision ledger, including duplicate evidence. Filter Validation_Status to Rejected or Duplicate; read Cleaning_Notes and Source_File. Only Accepted rows enter Financial_Statements and Financial_Ratios. The dashboard uses the newest accepted year for each company and charts the selected company's latest currency only. Peers may have different year ends; a bank and an industrial company are not automatically economic peers.

For an individual PDF choose Company on Home and the company ID on Dashboard. Comparison uses one latest accepted record per issuer. Generate previews the Report sheet; Export rebuilds it and writes a timestamped PDF. To inspect reported source EV and earnings inputs, follow the corresponding Financial_Ratios formula into Financial_Statements. Redo the full workflow after editing source data. See [metric rules](FORMULAS.md).
